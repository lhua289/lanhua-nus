NUS HUB Agentforce — Builder Project Hub

Open index.html. Three items have separate purposes:

01 Discovery Workshop — kickoff/index.html
18 core slides to agree the use-case, audiences, business value, expected
agent behaviours, requirements, delivery scope, responsibilities and plan.
Possible risks are highlighted. NUS behaviour expectations and scripted
conversation examples are edited here. Seven workshop sheets open on demand.

02 Use Case Design — design/index.html
One editable Pre / During / Post Agent Blueprint. Its six supporting sheets
cover scenario configurations and data/grounding. Sub-agents, actions,
sources, instructions, inputs/outputs and checks belong here. This is an
illustrative design to validate with NUS, not inspected org configuration.
Configuration links from Discovery open the matching sheet in Design.
The Design sheets link back to the relevant Discovery context.

03 Build Review — build-review/index.html
A placeholder only. We will update it once the build starts, using the
working agent, actual configuration and test evidence.

Controls
Portal sidebar: navigate between the three items; Hide menu collapses it.
In a presentation:
  Portal: return to the project hub
  Left / Right or Slides / S: navigate
  Notes / E: edit decisions and To confirm fields
  Edit behaviours / D in Discovery: capture expected responses and rules
  Edit design / D in Use Case Design: edit the worked design
  More: worksheets, reading view, JSON export/import, save HTML and print
  Present: browser full screen
  Pause motion: stop animations where available

Walk through in Discovery opens a scripted example, not a live agent.
Configuration opens the corresponding Design worksheet. Keep entries
concise for presenting; use reading view for longer notes.

All four audiences remain in scope: Prospective Student / Learner,
Applicant, Student and Alumnus. Confirm sign-in routes, NUS-ID eligibility
and content permissions for every audience. General FAQ guidance does not
imply permission to retrieve personal records or create cases.

Builder delivers the agreed scope and a working agent in the NUS full-copy
sandbox, then supports handover and the move to production. NUS and delivery
partners own project delivery, approvals, rollout, testing and operations.

Notes and compatibility
Each presentation saves its own inputs in the current browser. Edits do not
change GitHub, the original HTML or another viewer's copy. Export JSON or
save HTML with notes to keep and share them. Import into the presentation
that exported the file. Local and hosted browser storage are separate.

Earlier Discovery and Design inputs from removed duplicate sections remain
in exports and saved HTML. They are not automatically merged into another
presentation. Earlier Build Review browser storage is untouched; if notes
exist, the placeholder offers an export button.

Old root #slide-N links redirect to Discovery. Older Design slide links now
open the single blueprint. Each presentation has a Portal link. Saved HTML
copies link to the hosted portal and related presentation.

Keep the portal directory and assets together for offline viewing.
Print/PDF includes core slides only; worksheet inputs stay in HTML/JSON.
Enable background graphics and check the browser print preview.
